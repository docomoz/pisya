# Размещение на отдельном Ubuntu VPS

Комплект предназначен для нового выделенного сервера. Он не покупает сервер, не меняет DNS и не заменяет конфигурацию других сайтов. Нужны Node.js 22 или новее по пути `/usr/bin/node`, Caddy, systemd и доступ с правами sudo. На сервере должны быть открыты входящие TCP-порты 80 и 443; порт приложения 4174 слушает только `127.0.0.1` и наружу не открывается.

Сервер должен обращаться к GitHub по HTTPS: `/download` при каждом запросе получает appcast последнего релиза, проверяет адрес DMG и перенаправляет на него. При ошибке показывает страницу с ссылкой на релиз вместо устаревшего файла.

## Подготовка пакета

В проверенном исходном состоянии репозитория выполнить на машине с Node.js 22+, где доступен `tar`:

```sh
cd website
npm test
node scripts/package-vps.mjs /tmp/pisa-site.tar.gz
```

Пакет содержит собранную серверную часть вместе с ресурсами страницы, unit для systemd, конфигурацию Caddy и установщик. Учётные данные, сайт Sites и другие файлы из проекта в него не включаются. Служебный `.openai/hosting.json` для сборки пакета не нужен.

Публичный идентификатор веб-потока Google Analytics 4 хранится в `analytics.json` в поле `gaMeasurementId`: обычные сборки автоматически подхватывают его. Пустая строка отключает аналитику. Для разового переопределения задайте `PISA_GA_MEASUREMENT_ID` в окружении сборки; для совместимости также поддерживается прежняя `PISYA_GA_MEASUREMENT_ID`. Новая переменная имеет приоритет, а пустое значение явно отключает счётчик. Сборка выводит используемый идентификатор или `disabled` — перед публикацией проверяйте это значение. События: `page_view`, `install_guide_click` (параметр `cta_location`: `header`, `hero` или `install`), `download_click`, `github_click` (параметр `github_destination`: `source`, `install_guide` или `privacy`), `copy_install_command` и `contact_click`. `download_click` означает попытку скачивания, а не подтверждённое получение файла; `copy_install_command` отправляется после успешного копирования. В настройках потока GA4 отключите расширенную статистику по исходящим ссылкам и скачиванию файлов, чтобы не считать их дважды. Параметры URL и текст, введённый посетителем, в события явно не передаются.

## Установка

Проверить IP нового сервера, ключ SSH, что этот IP отличается от IP Mapfav, и что выбран нужный отдельный аккаунт. Установить Node.js и Caddy из их официальных источников. Скопировать пакет на сервер, указав его адрес и имя пользователя вместо примера:

```sh
scp /tmp/pisa-site.tar.gz USER@SERVER:/tmp/pisa-site.tar.gz
```

Подключиться к серверу и установить приложение:

```sh
mkdir -p /tmp/pisa-site-install
tar -xzf /tmp/pisa-site.tar.gz -C /tmp/pisa-site-install
sudo sh /tmp/pisa-site-install/deploy/install.sh
curl -i http://127.0.0.1:4174/
curl -I http://127.0.0.1:4174/download
```

Установщик сохраняет каждую версию отдельно в `/opt/pisa-site/releases/`, переключает ссылку `current` и перезапускает только `pisa-site.service`. Он не затрагивает Caddy и откажется перезаписывать не принадлежащий этому комплекту unit. Для обновления повторить сборку, копирование и установку нового пакета.

## Домен и HTTPS

В DNS задать для `getpisa.app`, `www.getpisa.app`, `pisya.app` и `www.pisya.app` A-записи на IP сервера. Запись AAAA добавлять только при настроенном и проверенном IPv6 этого сервера. Не включать проксирование DNS-провайдером, если требуется, чтобы публичный IP домена был именно IP VPS. Дождаться, пока все записи действительно укажут на сервер, прежде чем включать HTTPS.

Файл `deploy/Caddyfile` проксирует `getpisa.app` к приложению, а `www.getpisa.app`, `pisya.app` и `www.pisya.app` перенаправляет на основной домен, сохраняя путь и параметры запроса. Сначала сохраните копию действующей конфигурации и добавьте только блоки новых доменов; старые блоки и службу оставьте работающими. Когда новый feed и скачивание проверены, замените старые блоки соответствующими перенаправлениями из файла. Не создавайте повторных блоков для одного имени и не затирайте настройки других сайтов. Перед каждым переключением проверьте и примените итоговую конфигурацию:

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy получает и обновляет TLS-сертификаты автоматически после того, как все имена указывают на сервер и порты 80/443 доступны извне. Проверить с внешней сети `https://getpisa.app/`, переходы со всех трёх дополнительных имён с сохранением пути и параметров запроса, сертификат, внешний IP и `/download` (включая реальное начало скачивания DMG в браузере). Если GitHub с IP VPS недоступен, `/download` честно вернёт 503; это нужно проверить именно после переноса. Логи приложения: `journalctl -u pisa-site.service`.

Перед переключением сайта убедитесь, что опубликован `pisa-updates.xml` и указанный в нём DMG доступен: до этого `/download` вернёт 503. Сохраняйте прежний `appcast.xml` для установленных версий Pisya; он не используется сайтом Pisa. Новая служба `pisa-site` и порт 4174 работают отдельно от прежней `pisya-site` на порту 4173; старую службу оставьте включённой до проверки нового релиза и переключения доменов.
